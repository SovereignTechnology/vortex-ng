# 3. Pits: sw0, tr0 and wsh0

Date: 2026-11-09

## Status

Accepted

## Context

JoinMarket-NG's taproot work (JMP-0010, PR #643) introduces the "pit": a coinjoin pool for one script family,
with its own offer types, and "pits never mix". JMP-0010's input-uniformity rationale already names
taproot Lightning funding outputs as something a `tr0` round should hide.

Regular (non-taproot) Lightning channels are funded by BOLT 3's P2WSH `2 <key1> <key2> 2 OP_CHECKMULTISIG`
with the two keys in lexicographic order. Inside a `sw0` round, such an output is the only P2WSH among
P2WPKH outputs, so it marks the taker's output. LnVortex hid it by making every output in its Lightning rounds
P2WSH.

## Decision

- `sw0`: JMP-0001 as specified. `tr0`: JMP-0010 as specified at the pin.
- `wsh0` (new, `docs/jmp/jmp-draft-wsh0-pit.md`): every input and output is P2WSH
  `wsh(sortedmulti(2, K_a, K_b))`. Wallet coins in this pit are 2-of-2s whose two keys both belong to the
  wallet, so they match a channel funding output's script when created and when spent (two signatures, the
  same witness script template).
- Wallet paths match joinmarket-ng (BIP84 for `sw0`, BIP86 for `tr0`), so a seed restores in either; the
  `wsh0` path is proposed in its draft. Fidelity bonds stay the P2WSH timelocked bond on the `sw0` bond path
  for every pit (JMP-0010 "Fidelity Bonds").
- Unsupported: legacy and wrapped-segwit offer types.

## Consequences

- One process and one wallet account set per pit, as joinmarket-ng runs them; liquidity is accounted per
  script family.
- A `wsh0` wallet needs deposits to 2-of-2 addresses, and its inputs cost more to spend (two signatures).
